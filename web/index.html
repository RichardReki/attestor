An agent may propose anything.

It cannot fabricate the fact it acts on.

Authorisations happen on Ethereum Sepolia. An off-chain agent decides which ones to carry to Creditcoin. A contract there re-derives every one from the proven transaction, so the agent's judgement is never the last word — and neither is ours.

Honest status: the source contract is live on Sepolia and the proof pipeline is verified against the real precompiles (below). The consumer contract that acts on Creditcoin is written and tested but not yet deployed — the first on-chain execution is waiting on CC3 testnet funds.

The gap is the constraint

A Sepolia block cannot be proven until it is attested, and the prover refuses anything inside a 32-block reorg-protection window. Everything between these two marks is real, final on Sepolia, and not yet provable on Creditcoin. An agent built here acts on facts that are minutes old. What a proof settles

Attestcoin answers one question, precisely. Reading it as an answer to a larger one is where a consumer contract gets exploited, so the governor treats everything on the right as its own job.

It proves
  • This transaction was included in a confirmed Sepolia block.
It does not prove
  • That it succeeded. A reverted transaction sits in the block and proves perfectly.
  • That it called your contract. Any contract's call carries the same weight.
  • That it called your function. The right contract, the wrong entry point.
  • That the sender was authorised. Authority belongs to the signer, not the relayer.
  • That it is recent. An attested fact stays provable for ever.
  • That you have not already acted on it. Nothing stops a second submission.

Behaviour the documentation does not describe

Found while building, each one load-bearing. Two of them make a consumer written from the documentation fail outright.

  1. The BlockProver precompile reverts on a bad proof. The SDK types it Promise<boolean> and documents "false otherwise", so an if (!verified) branch is dead code.
  2. End-to-end latency is about eight minutes — a 32-block reorg-protection window, named only inside a BlockNotOnSourceChain error, plus roughly 39 blocks of attestation lag.
  3. chainKey is environment-scoped. Key 1 is Sepolia here and Ethereum mainnet on CC3 Mainnet, so a contract promoted between them silently changes which chain it trusts. Bind to chainId.
  4. Names differ from the SDK in both directions: the precompile function is verify, not verifySingle, and ChainInfo is snake_case on-chain.
  5. The proof envelope is (uint8 txType, bytes[] chunks), not bytes[] — which is what the SDK's own comment, three lines above the implementation that contradicts it, tells you to decode.
  6. The precompiles cannot be fork-tested. They are Substrate runtime code, so eth_getCode returns 0x; a forked node has nothing there, and calls to a codeless address succeed silently. Fork tests pass the wrong assertions.
  7. get_chain_by_key returns one tuple containing (Chain, bool), not two values. Chain holds a bytes, so the encodings differ by a level of indirection. Every mocked test passed; the live chain always reverted.
